# External deployment-job admission

External `application.deploy.low-risk`, `application.deploy.production-like` and `service.deploy` leases require a protected job admission on claim, renewal and receipt. An omitted guard or job policy denies deployment. Existing central service plans retain their current execution path.

An administrator first applies a CI enrollment whose protected `jobClass` is `deployment`; omitted or `build` class cannot authorize deployment. Register a distinct purpose-scoped deployment executor identity and existing exact execution/read grants. The enrolled repository, immutable revision, workflow file digest, event, ref, job, runner group and labels remain controlling. Enrollment is not host or job qualification.

Prepare one exact `ciDeploymentJobs` server-profile binding with its enrollment and digest, execution binding, executor, target, artifact digest, numeric provider run/attempt/job/runner. Its execution binding supplies only the existing active `ci.assignment.read` observer credential; organization registration and deployment tokens are not delivered by this path. The existing applied credential capability and verified native resolver must be available. No credential values belong in this profile.

Seal `serverconfig.CIDeploymentJobDigest(binding)` in the declaration/plan extension `x-executor-deployment-job`. This digest omits the derived plan ID and digest to avoid a cycle. After the exact immutable plan is prepared, configure its derived ID/digest on that protected binding. Human approval remains necessary for production-like deployment. Profile changes do not create or acknowledge a plan.

The job uses existing executor lease claim, renewal and receipt APIs. The server reads the current applied enrollment and fresh actual numeric job through its fixed GitHub observer before each boundary, checks credential identity around I/O, and repeats current run authorization afterward. Any drift, untrusted/build job, completed/cancelled job, stale observation, outage, revoked policy or mismatch denies that boundary. No automatic effect replay is introduced. A caller-authored receipt still requires the existing independent target verifier.

This is an admission prerequisite. It does not implement narrow deployment credential handoff, add a deployment adapter, convert Phase8 central plans into external plans, or qualify a live GitHub job. External credential-bound plans remain blocked. Those remaining integrations and a real combined demonstration must pass before protected deployment or Phase9 completion is claimed. Provider reads remain non-atomic; the exact job can change after an observation. No provider, runner, VM, credential, fleet or CI dispatch is authorized by this procedure alone. Nodes04/05 stay excluded.
