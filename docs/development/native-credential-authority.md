# Native credential authority (development fixture)

This profile is dormant until #140's exact mapping, #143's real disposable-systemd acceptance, and #141's lifecycle verifier are independently reviewed and integrated. It grants no inventory-host installation or gate activation.

The unprivileged `vsk-labs server run` account is `vsk-labs`. The Ansible role under `ansible/roles/native_credential_authority` accepts an explicit sorted `.service` list, the local 32-character machine ID, and exact sorted probe tuples (`unit_name`, `credential_name`, non-root `uid`, non-root `gid`). The tuples must be derived from the #140 sealed positive and denied reader map. The role requires `/usr/local/bin/vsk-labs` to be a root-owned regular executable with no group/world write bit, then installs one root-owned polkit rule for `manage-units`/`restart` on enrolled units, one fixed-argument sudoers rule for the same binary's private probe mode, and one root-owned policy readable by the `vsk-labs` group. It does not grant start, stop, enable, daemon reload, transient units or arbitrary shell execution.

Before any disposable-host application, confirm Debian 13/systemd, polkitd, sudo, util-linux `nsenter`, Ansible and a separate approved exact fixture plan. Prepare two synthetic non-root service accounts plus `vsk-labs`; install a root-owned development build of the single binary at `/usr/local/bin/vsk-labs`. Prepare `vsk-native-allow.service` with `LoadCredential=credential-a:<synthetic-fixture-file>`, `User=vsk-native-positive`, and a long-running process, plus a distinct `vsk-native-other.service`. No real material belongs in the fixture. Apply the role using its explicit inputs. Check the rendered JavaScript syntax (`node --check < /etc/polkit-1/rules.d/49-vsk-native-credential-restart.rules` on the fixture), sudoers syntax (`visudo -c -f ...`), exact file ownership/modes, and polkitd startup/logs before running the matrix. The [Debian polkitd manual](https://manpages.debian.org/trixie/polkitd/polkitd.8.en.html) confirms the daemon drops to the `polkitd` user; the [util-linux `nsenter` manual](https://kernel.googlesource.com/pub/scm/utils/util-linux/util-linux/%2B/refs/tags/v2.41.1/sys-utils/nsenter.1.adoc) documents the mount namespace path and `--setgid` group clearing.

On that disposable fixture only, create a root-owned mode `0600` `/run/vsk-native-authority-disposable` marker and run `VSK_NATIVE_AUTHORITY_DISPOSABLE=1 bash tooling/native-credential-authority-acceptance.sh`. The script checks allowed restart; rejected different unit, verbs, unit-file and transient operations; positive and denied direct-open outcomes under exact UIDs/GIDs; malformed/extra-argument rejection; and output canaries. Recheck the service process identity, namespace and credential inode before accepting a result. Record fixture image/systemd/polkit/sudo/nsenter versions, exact commit and sanitized test result in #143 evidence. Fixture-only success never closes G-007.

For removal or recovery on the disposable fixture, stop verifier use, remove the exact three role-owned files, verify restart and probe are both denied, then reapply the same reviewed role inputs and rerun the matrix. Do not remove a policy from an inventory host through this development procedure. A changed machine ID, executable inode or ownership, unit enrollment, reader tuple, target process, namespace or credential inode blocks verification until a new approved plan and role application requalify it.
