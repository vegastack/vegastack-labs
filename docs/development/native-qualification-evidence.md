# Native qualification evidence

The disposable native workflow uses the installed `vsk-labs` executable, its existing API, and the ordinary declaration, plan, Slack acknowledgement, and execution flow. A diagnostic native report is not applied evidence. Public gate uploads remain fixture evidence even when they copy a native payload or collector name.

The protected fixture scope pins the source, executable, guests, profile and original absolute deadline. `qualification inspect` reads an already authorized discovery target. `qualification native` coordinates only that scope. `qualification step` accepts a finite request from its fixed protected scenario slot; it accepts no shell script or arbitrary executable. The internal `collect-native` step loads its corresponding protected collection request, re-resolves the actual producer plans, released leases, receipts and measured results, and requests fresh observations through the protected channel. A failed or incomplete scenario cannot produce qualified evidence.

Collection stores an inert gate draft and its declaration. Inspect the returned submission, create the ordinary plan for that exact declaration revision, obtain its exact human acknowledgement, and execute through `apply`. Baseline qualification must be applied before role qualification; recovery qualification requires applied baseline and role qualification. The collector binds their exact evidence, bundle and artifact digests and rechecks them inside its write transaction.

A verified restore can explain a changed controller identity within the original fixture window. It does not carry an earlier recovery epoch's qualification forward. New baseline and role collection still require current-epoch producer executions and the exact persisted verified restore lineage. The final recovery stage additionally requires the actual replacement commit and its canary, continuity and alias ownership records.

If a collection response is lost, stop and inspect the known declaration `gate-evidence-<evidenceId>` at revision `1` through the existing declaration-read API, together with scoped audit history. A draft can exist before declaration creation completes; a missing declaration is not proof that nothing was written. Do not blindly repeat the mutation: collecting again creates fresh observation nonces and timestamps, so the same evidence ID can return a conflict or stale revision. This failure is intentional; it does not mean the original draft was applied. Never replace this inspection with an uploaded report, a database edit, or an invented successful receipt.

The finite disposable Slack peer is documented separately in [Native Slack fixture](native-slack-fixture.md). It is a qualification helper with an exact protected approval list and deadline, not a production notification service or an alternate approval path. Software tests and synthetic observations do not establish native acceptance, host admission, or permission to contact the fleet.

The existing local native producer lookup also returns the canonical `receiptDigest` from the same current, scoped execution join. Basic volume recovery preparation uses this digest to identify the actual prior volume observation. It is not a caller-supplied receipt or qualification proof; run/host read grants, scope and epoch checks remain required.
